## Context

仓库当前仅包含 OpenSpec 工作流，没有应用代码。目标是从零构建一个 Kotlin Multiplatform 本地优先密码管理器，覆盖 Android、Windows Desktop 和 Web。系统同时具有三类强约束：

- 恢复密码必须能在没有任何 Vault 数据时，结合 key 和恢复配方重建子密码。
- 恢复密码不得长期驻留内存；本机主密码和生物识别只用于解封装本机保存的恢复密码。
- 多个兼容 S3 目标既是备份副本也是多客户端双向同步副本，必须在并发、离线和删除场景下最终收敛。

用户名需要在解锁前显示，因此属于可见本机元数据；密码库业务内容、S3 凭据和同步事件全部属于敏感数据。GC 管理的 JVM/JavaScript 环境无法保证物理擦除所有内存副本，设计目标是避免不必要副本、使用可覆盖二进制缓冲区并缩短明文生命周期。

## Goals / Non-Goals

**Goals:**

- 使用共享领域模型、应用服务和 Compose Multiplatform UI 实现三端一致行为。
- 建立版本化密码生成、加密 Vault、备份和同步协议，并提供跨平台固定测试向量。
- 将恢复密码、本机解锁、数据加密和生物识别硬件能力明确分层。
- 在多设备、多 S3 副本、离线编辑和并发冲突下保持数据可恢复和最终收敛。
- 以平台能力为边界实现安全剪贴板、后台锁定、原子持久化及退出提示。

**Non-Goals:**

- 不建设中心服务器、在线账户、共享密码库或多人实时协作。
- 不保存网站登录会话，不实现浏览器自动填充、浏览器扩展或云端明文索引。
- 不保证在受恶意操作系统、键盘记录器、进程注入、浏览器扩展或已攻破运行时下保护解锁后的数据。
- 不保证 Web/Android 在进程被平台强制终止时完成网络同步。
- 首版不自动解决 key 唯一性、目录环或超深层级等语义冲突。

## Decisions

### 1. Kotlin Multiplatform 分层

工程采用 Kotlin Multiplatform、Compose Multiplatform、Kotlin Coroutines、Kotlin Serialization 和 Ktor。按职责拆分为领域模型、应用用例、密码学门面、存储门面、同步引擎、共享 UI 及三个平台入口：

```text
androidApp / desktopApp / webApp
                │
             shared-ui
                │
          application/domain
          ┌─────┼─────┐
        crypto storage sync
          └──── expect/actual 与平台适配
```

领域层不得依赖平台 API；文件、IndexedDB、生物识别、剪贴板、生命周期和安全随机数通过接口或 `expect/actual` 注入。相比三套独立客户端，该方案可以让生成协议、合并规则和 UI 状态机共享测试，降低跨平台结果漂移风险。

### 2. 恢复密码与本机解锁分层

创建用户时生成 256 位随机 `LocalEnvelopeKey`（LEK）：

1. 恢复密码经 UTF-8 编码后作为敏感字节，由 LEK 使用 AEAD 加密保存到本机。
2. 本机主密码经带随机盐和可记录参数的 Argon2id 派生本机包装密钥，再封装 LEK。
3. 生物识别启用时，由 Android Keystore、Windows 平台安全密钥或受支持 Web 平台能力封装同一 LEK。
4. 授权会话只缓存 LEK，不缓存本机主密码、恢复密码或可导出的生物识别私钥。
5. 每个敏感操作取得许可后，用 LEK 临时解密恢复密码，派生限定用途密钥，随后覆盖恢复密码和中间缓冲区。

采用 LEK 而不是让本机主密码直接加密全部 Vault，可以允许每台设备设置不同本机主密码、重置本机解锁而不改变生成结果，并避免将任何本机认证材料写入备份。LEK 只保护本机恢复密码，不作为 Vault 数据密钥。

### 3. 密码学协议与用途隔离

首选经过审计且三端可获得一致实现的 Argon2id、HKDF-SHA-256、HMAC-SHA-256 和 XChaCha20-Poly1305；以密码学门面隔离具体库。实施前通过依赖验证任务确认 JVM、Android 和 WebAssembly/JavaScript 绑定的维护状态和测试向量，不能满足时选择提供同等原语的经审计实现。

- 本机包装：`Argon2id(本机主密码, 随机本机盐, 头部参数)`。
- Vault 数据：`Argon2id(恢复密码, 随机 Vault 盐, 头部参数)` 后通过 HKDF 派生 DataKey、SyncKey 和 BackupKey。
- 密码生成：`Argon2id(规范化恢复密码, 固定协议盐与冻结参数)` 得到 V1 GeneratorKey。
- 所有 AEAD 将格式版本、VaultId、算法标识和必要头部作为附加认证数据。

数据 KDF 参数可以随格式升级并写入头部；生成 KDF 参数必须冻结在 V1 协议中，否则会改变无数据恢复结果。恢复密码采用 Unicode NFC 后 UTF-8 编码以保证跨平台一致性；界面必须明确提示空白和 Unicode 字符均是密码的一部分。

### 4. V1 确定性密码生成

恢复配方使用确定性 CBOR 表达并以 Base64URL 包装，外层格式为 `hdpwd-recipe:v1:<payload>:<checksum>`。载荷包含 key、算法版本、长度、允许字符类、每类最小数量、符号集合和排除字符。

V1 生成流程固定为：

1. 校验区分大小写的 ASCII key 和规范化规则。
2. 使用 GeneratorKey 对带域前缀的 key 与规范化配方运行基于 HMAC 的计数器流。
3. 通过拒绝采样从允许字符集合选择字符，避免取模偏差。
4. 先满足各字符类最小数量，再填充剩余位置。
5. 使用同一确定性流执行 Fisher-Yates 洗牌，避免必选字符位置固定。
6. 仅将结果保存在当前显示、复制或恢复操作的可覆盖缓冲区。

V1 发布前必须产生公开的输入、配方编码、中间摘要和最终密码测试向量。未来协议新增 V2，不得修改 V1。

### 5. Vault 模型和本地持久化

Vault 使用不可变 UUID 标识用户数据对象，密码项 key 只是可变生成字段：

```text
VaultState
├─ VaultId、schemaVersion
├─ Folder(id, parentId, name, color)
├─ Entry(id, parentId, key, title, labels, policy, generatorVersion, color)
├─ SyncTarget、SyncState
├─ Tombstone、Conflict
└─ DeviceClock、AppliedEvent
```

根目录视为第一级，目录写入前校验最大三级、无环和父对象存在。搜索只在解锁后的内存模型上构建，不生成或持久化子密码。

Android/Windows 以“临时文件写入、认证读取校验、原子替换”提交完整加密 Vault 快照，并保留最后成功版本。Web 使用 IndexedDB 单事务提交加密 Blob、用户索引和同步 dirty 状态。用户名仅存在最小明文本机索引；文件和对象名使用随机标识。

选择完整快照作为首版本地事实源，是因为预期 Vault 规模较小且更容易验证崩溃一致性；S3 仍使用增量事件以降低网络和对象操作成本。

### 6. 授权和敏感操作许可

会话状态机具有 `Locked`、`Unlocked(expiresAt, LEK)` 和 `Expiring` 状态。五分钟为绝对期限，不因操作刷新。敏感操作在开始时原子取得包含用途和取消状态的许可：

- 到期后不再签发新许可并立即要求验证。
- 已签发操作复制或派生最小必要材料，可以完成当前原子流程。
- 操作完成即覆盖临时密钥；最后一个活动许可完成后清理过期会话。
- 返回用户列表、取消验证和删除用户强制清理解密 Vault 与 UI 状态。

该模型避免在导出或一次同步加密的中途破坏文件，同时保证到期后不能启动新的密码生成、导出或配置解密。

### 7. 备份容器

`.dat` 使用版本化二进制容器：

```text
magic | formatVersion | KDF/AEAD 参数 | salt | nonce | encryptedPayload
```

载荷包含 VaultState、同步历史所需状态和 S3 配置，不包含用户名、本机恢复密码密文、LEK 包装、生物识别材料或生成密码。文件名使用经过安全转义的用户名和本地时间，但文件名不参与导入。

导入在临时区域完成认证解密、结构约束和 key 唯一性验证，再原子创建本地用户。恢复出的同步目标默认待确认。全库迁移只迁移当前本地和已连接同步副本，不尝试修改用户已导出的历史文件。

### 8. 多 S3 副本同步协议

S3 功能按多主复制设计，不以覆盖单个“最新备份文件”实现。建议对象布局：

```text
vault/<VaultId>/
├─ protocol/<version>
├─ devices/<DeviceId>/head
├─ deltas/<DeviceId>/<sequence>.dat
└─ snapshots/<SnapshotId>.dat
```

每个五秒静默窗口形成一个加密 delta 包。事件含 EventId、DeviceId、设备序号、因果版本、HLC、EntityId、操作、字段变更和可选事务标识。对象路径仅包含随机标识和序号。

客户端从全部已确认目标拉取未知事件，按 EventId 去重，在本地合并后把每个目标缺失的事件传播到其他目标。每个目标维护独立水位和健康状态；网络操作使用指数退避与随机抖动。实现兼容 S3 Signature V4 的共享客户端及厂商 endpoint、region、path-style 等预设，凭据只在签名期间临时解密。

### 9. 合并、冲突和墓碑

设备序号和因果版本用于判断可比较更新，HLC 与 DeviceId 只在并发同字段时提供确定性当前值：

- 因果更新覆盖旧值。
- 并发不同字段自动合并。
- 并发同字段确定性选值，并保留另一个候选及冲突元数据。
- 删除使用墓碑；删除与更新并发时删除优先，但保存可恢复候选。
- 两个不同 EntryId 占用同一 key、目录形成环或超过三级时进入人工冲突状态，绝不自动改 key。
- 文件夹级联删除以事务标识产生整个子树墓碑。

定期快照包含当前状态、冲突、墓碑和每设备水位。只有确认快照覆盖后才回收增量，必要墓碑永久进入压缩快照。相比仅使用操作时间的 Last-Write-Wins，该设计能抵抗时钟偏差并避免离线设备复活删除数据。

### 10. UI 和平台安全适配

共享 UI 使用单向数据流和状态容器实现用户列表、验证、密码库、编辑、设置、冲突及恢复页面。窄屏使用单列，宽屏按卡片最小宽度自动增列。密码显示、剪贴板计时和会话计时使用可测试时钟。

- Android：应用私有文件、BiometricPrompt/Keystore、平台剪贴板和生命周期。
- Windows：应用私有目录、可用的 Windows 硬件/用户验证密钥、剪贴板和可等待的窗口关闭流程。
- Web：IndexedDB、Page Visibility、`beforeunload` 尽力提示；仅在浏览器能稳定封装本机密钥时启用生物识别，否则回退主密码。

任何日志、埋点和异常包装在共享脱敏接口后；生产构建禁止记录敏感对象的默认 `toString`。S3 只通过验证 TLS 发送认证加密数据和协议所需签名。

## Risks / Trade-offs

- [恢复密码熵不足会导致离线猜测并同时危及 Vault 和所有子密码] → 创建时提供强度检测，推荐多个随机词组成的长密码，使用 Argon2id，并明确不存在服务端找回。
- [固定生成 KDF 参数未来可能显得偏弱] → V1 永久兼容，新增 V2；恢复配方显式携带版本，用户主动迁移密码项。
- [GC 运行时无法保证物理清除全部副本] → 使用二进制缓冲区、避免不可变字符串和隐式日志，限制敏感值作用域并尽力覆盖。
- [Web 生物识别和关闭等待能力不统一] → 运行时能力检测，不满足即回退本机主密码；持久化 dirty 状态而不承诺关闭时完成同步。
- [兼容 S3 厂商在签名、列举一致性和 CORS 上存在差异] → 建立提供商测试矩阵、连接诊断和预设覆盖，协议只依赖基础对象操作。
- [多主同步事件和永久墓碑会持续增长] → 使用加密快照、水位和安全压缩；绝不为节省空间提前删除阻止复活所需信息。
- [多个 S3 目标会把一处数据传播到全部副本] → 设置页明确同步集合语义，新发现目标必须确认，提供按目标暂停和诊断。
- [全库迁移会改变全部生成密码且远端迁移可能部分失败] → 使用新 epoch 和两阶段提交保留旧数据，全部目标完成前允许回滚旧恢复密码。
- [完整本地快照写入会随 Vault 增大而变慢] → 首版优先一致性；基于指标再引入本地分块或增量存储，保持外部格式兼容。

## Migration Plan

1. 建立 KMP 工程、共享模块和三端空壳，完成依赖与密码学原语兼容性验证。
2. 固定 V1 生成协议、恢复配方和加密容器格式，生成跨平台测试向量后再实现业务 UI。
3. 实现本地用户、LEK 封装、授权许可和各平台安全存储。
4. 实现 Vault 领域模型、实时本地持久化、导入导出和敏感交互。
5. 实现 S3 单目标协议与故障恢复，再扩展到多目标拉取、合并、传播、快照和冲突 UI。
6. 通过跨平台一致性、断电恢复、并发同步、离线设备、平台生命周期和安全日志测试后发布。

项目当前没有旧数据或旧客户端需要迁移。协议尚未发布前允许调整格式；发布 V1 后所有不兼容变化必须使用新版本和显式迁移。

## Open Questions

- 构建与验证统一在 Docker Compose 中执行，宿主机不要求安装 JDK、Gradle 或 Android Studio。普通 KMP、Desktop 和 Web 任务使用 JDK 17 Gradle 镜像，Android 任务使用带 Android SDK 的独立镜像。
- 本地 S3 集成测试使用 `pgsty/silo` 容器，其 S3/MinIO 兼容 API 配置三个独立 bucket，分别模拟三个同步目标；测试环境凭据只使用固定测试值，不得带入生产配置。
- 当前 Kotlin 2.1.20/Wasm 不提供 `JsFun`，而 Juul IndexedDB 0.12.0 的 Wasm 元数据需要更新的 Kotlin 编译器；Web IndexedDB 与 Page Visibility 适配需升级 Kotlin/Wasm 工具链或引入兼容的原生 JS bridge。
- Windows WebAuthn/Windows Hello 的硬件密钥封装需要真实 Windows 安全设备和桌面 API 测试环境，Docker Linux 构建只能验证接口和编译。
- 在实施依赖验证中确定三端共同可维护的 Argon2id 与 XChaCha20-Poly1305 库及其供应链固定方式。
- 建立阿里云、腾讯云、七牛云和通用 S3 的 endpoint、签名、path-style、CORS 与一致性测试矩阵。
- 通过性能基准确定本机主密码 KDF、Vault KDF 和冻结生成 KDF 的具体 V1 参数，并确保最低支持设备可接受。
