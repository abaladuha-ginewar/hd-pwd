## Context

当前本机解锁是每用户一把主密码：创建用户时同时收集恢复密码和本机主密码，点选用户先过整页解锁，五分钟会话只缓存该用户的 `LocalEnvelopeKey`（LEK）。生物识别封装也按用户存储，解锁页把指纹按钮和主密码框并列，不会按「本机是否一开始就选用生物识别」决定默认验证方式。

这与产品意图不符。主密码和生物识别应是**这台设备**解开本地恢复密码缓存的钥匙，而不是每个密码库账户的登录口令。用户列表保持可见；真正加解密（创建用户、打开用户、保存/显示/同步、改设备锁）才验证。Vault 数据密钥、备份和 S3 仍只由各用户恢复密码派生，本机材料不得离开设备。

约束：三端共享领域与 UI；Web 无稳定生物识别；Argon2id 主密码派生成本高，不适合每次按键都跑；GC 运行时仍只能尽力覆盖敏感缓冲。

## Goals / Non-Goals

**Goals:**

- 将本机主密码收成安装级一把，用随机 `DeviceLEK` 封装各用户缓存在本机的恢复密码。
- 首次安装强制设置主密码，可选生物识别；用户列表不锁，首页提供设备设置。
- 创建/导入用户、打开用户、改 DeviceLEK 相关设置必须先通过设备验证；验证默认跟随本机生物识别偏好，并允许切到主密码。
- 保留五分钟绝对授权会话：只缓存 DeviceLEK；到期清除 DeviceLEK 与任何已解密 Vault，若当时在密码库内则回到用户列表。
- 修改主密码保持 DeviceLEK 不变；忘记主密码则轮换 DeviceLEK，仅重绑当时验证成功的那个用户，其余用户待用其恢复密码重新绑定。
- 一次性把已有的每用户本机封装迁到设备锁。

**Non-Goals:**

- 不改变恢复密码、Vault DataKey、密码生成、备份格式或 S3 协议。
- 不把用户列表或用户名藏到设备锁后面。
- 不为 Web 补做不稳定的生物识别。
- 不在本次引入 PIN、锁屏超时可配置、多设备主密码同步。
- 不把恢复密码全库迁移放进首页设备设置（它仍属于单个用户）。

## Decisions

### 1. 设备级 DeviceLEK，而不是共用主密码去包装每用户旧 LEK

采用单一随机 256 位 `DeviceLEK`：

1. 本机主密码经 Argon2id（现有本机 KDF 参数）派生包装密钥，AEAD 封装 DeviceLEK。
2. 若启用生物识别，平台能力再封装**同一把** DeviceLEK。
3. 每个本地用户的恢复密码用 DeviceLEK 做 AEAD 加密，附加认证数据包含用户 id 与设备锁世代，密文只存在本机。
4. 授权会话只缓存 DeviceLEK；打开某个用户时才临时解密该用户恢复密码，用完覆盖。
5. Vault 仍由该用户恢复密码派生 DataKey 加密。

备选是「每用户保留 LEK，再用设备主密码包装这些 LEK」。层次更多，忘了主密码时照样要轮换外层钥匙，对隔离帮助有限：会话里一旦有设备包装密钥，仍可解开所有用户 LEK。因此直接让 DeviceLEK 封装恢复密码，少一轮密钥。

会话持有 DeviceLEK 意味着五分钟内理论上能解开本机缓存的所有恢复密码。这是设备锁的本意。实现上仍按需解密单个用户，不在验证成功时批量解开。

### 2. 设备锁记录与用户索引分离

新增独立本机记录（不进用户索引、备份、S3）：

- `generation`：设备锁世代（随机 id）。忘记主密码并轮换 DeviceLEK 时递增/更换。
- `wrappedDeviceLek`：主密码包装的 DeviceLEK。
- `preferBiometric`：本机是否以生物识别为默认验证方式。
- 生物识别密文单独存放；有无文件表示当前能否用生物识别解开，与偏好分开。

每用户恢复密码封装带有 `deviceGeneration`。与当前设备锁世代不一致则视为**待重绑**，不得用旧密文去试新 DeviceLEK。

用户索引继续只含随机用户 id、用户名、存储定位等非敏感字段，可在未验证时读取。

### 3. 何时验证、会话在用户列表是否保留

验证发生在需要 DeviceLEK 或恢复密码的动作上，而不是进入应用时：

| 动作 | 需要验证 |
|---|---|
| 启动并显示用户列表 | 否 |
| 打开设备设置页 | 否 |
| 创建设置中的生物识别/主密码 | 是（会改包装） |
| 创建/导入用户 | 是（写入恢复密码封装） |
| 点选用户解密 Vault | 是 |
| 会话内保存、显示密码、同步、导出 | 否（使用缓存 DeviceLEK） |
| 会话到期后再做上述操作 | 是 |

五分钟绝对期限不因操作刷新。**返回用户列表不清除 DeviceLEK**，只清该用户的解密 Vault、搜索索引和临时恢复密码。这样在窗口内创建另一用户或打开另一用户不必再验。到期则清除 DeviceLEK；若当时密码库仍打开，同时清理解密状态并回到用户列表。

已取得操作许可的导出/同步仍允许做完；新敏感操作拒绝。验证取消：不留下半个已解密界面，回到用户列表。

首次设置设备锁成功后立即打开一轮会话，便于马上创建第一个用户。

### 4. 验证 UI：偏好与能力分离

`preferBiometric` 记录用户选择（首次安装或设备设置中最后一次成功开关）。是否存在有效生物识别封装是另一件事。

- 偏好为开且平台 `AVAILABLE`：自动拉起系统生物识别，提供「使用主密码」。失败或用户切换则主密码框，不得损坏 DeviceLEK 或用户封装。
- 偏好为开但硬件/权限/密钥失效：出主密码框，不悄悄把偏好改成关。
- 偏好为关或 Web：只出主密码；提供「忘记主密码」。
- 平台不支持时，设置页不显示生物识别开关。

生物识别与主密码是等价解锁：能解开 DeviceLEK 即可修改主密码（用同一把 DeviceLEK 重新包装）。这样指纹用户忘了主密码时不必走破坏性的世代轮换。

### 5. 修改主密码 vs 忘记主密码

**修改主密码**（仍能验证）：解开现有 DeviceLEK → 用新主密码重新包装 → 若生物识别为开则再封一次。所有用户封装的 `deviceGeneration` 不变。

**忘记主密码**（无法解开 DeviceLEK）：

1. 用户选择一个本地用户并输入该用户恢复密码。
2. 系统用恢复密码直接认证解密该用户 Vault（不经过 DeviceLEK）。
3. 生成新 DeviceLEK 和新世代，用新主密码及可选生物识别包装。
4. 将该用户恢复密码封装到新 DeviceLEK。
5. 其他用户封装因世代不匹配成为待重绑；点选时改为「输入该用户恢复密码以重新绑定」，成功后封装到当前 DeviceLEK。不得用 A 的恢复密码重绑 B。

旧 DeviceLEK 及旧生物识别封装作废。

### 6. 创建/导入与首页设置

创建/导入表单不再收集本机主密码或生物识别勾选。流程为：若无有效会话则先验证 → 用户名 + 恢复密码 + 可选备份 → 用当前 DeviceLEK 封装恢复密码并写 Vault。导入失败仍不得留下半成品用户。

首页设备设置（用户列表即可进）：

- 生物识别开关（无能力则隐藏）
- 修改主密码
- 忘记主密码 / 用恢复密码重置

密码库内设置仍只放 S3 等用户级项。恢复密码全库迁移仍在用户上下文：迁完后把**新**恢复密码重新封装到**现有** DeviceLEK，不改设备锁世代。

删除本地用户只删该用户 Vault 与恢复密码封装，即使删光用户也不删设备锁。卸载或清应用数据才去掉设备锁。

### 7. 继续复用现有密码学门面

不引入新算法。DeviceLEK 包装沿用 `LocalEnvelopeService` 的 Argon2id + AEAD 容器；生物识别继续走现有 `BiometricProvider`（label 改为设备级而非用户 id）。`AuthorizationSession` 缓存对象从每用户 LEK 改为 DeviceLEK，许可用途补上创建用户与设备设置。

## Risks / Trade-offs

- [会话中的 DeviceLEK 能解开本机所有用户的恢复密码缓存] → 这是设备锁语义；按需解密、五分钟绝对过期、回列表即丢 Vault 明文，降低暴露面。
- [忘记主密码会让其他用户进入待重绑] → UI 明确提示；Vault 密文仍可用各自恢复密码打开；不把「修改」和「忘记」合成一个按钮。
- [返回用户列表仍保留 DeviceLEK，手机放桌上五分钟内可打开另一用户] → 用绝对五分钟而不是「回列表即锁」换取创建/切换少验一次；到期必清。若以后要更严，可加显式锁定而不改密钥模型。
- [旧数据每用户主密码与新模型不兼容] → 启动时检测并走迁移向导，失败保留旧封装不删 Vault。
- [Web 无生物识别] → 能力检测后隐藏开关，仅主密码；与现有 Web 策略一致。
- [生物识别可改主密码] → 攻击者需能通过系统生物识别；这与「指纹等于解锁」一致。关闭生物识别或修改开关本身也要先验证。

## Migration Plan

1. 无设备锁且无用户：走首次安装设置主密码（及可选生物识别），再进空列表。
2. 无设备锁但存在旧的每用户封装：先设置新的设备主密码；再对每个用户要求旧本机主密码或该用户恢复密码，解开旧 LEK/Vault 后把恢复密码封装到 DeviceLEK。全部成功或用户跳过（跳过的用户标为待重绑）。不得在迁移失败时删除 Vault。
3. 已有设备锁：正常进用户列表。
4. 回滚：若需紧急回退版本，旧客户端不认识设备锁记录，无法用新封装解锁；因此迁移前应视为单向。发布前在测试数据上验证往返。本 change 在正式数据上执行迁移即不可自动回滚。

## Open Questions

无。探索阶段已确定：设备级一把主密码、列表不锁、到期清 Vault、保留五分钟、首页可开关生物识别与改主密码、Web 仅主密码。
