## Purpose

定义多兼容 S3 同步目标、五秒静默同步、不可变同步身份与增量、多副本最终收敛、冲突合并、墓碑与快照水位，以及同步配置确认、状态反馈与平台关闭行为。

## Requirements

### Requirement: 多个兼容 S3 同步目标
系统 SHALL 允许每个用户配置多个兼容 S3 的对象存储目标，并为通用 S3、阿里云、腾讯云、七牛云等提供可编辑的快速配置预设。每个目标 MUST 拥有独立的凭据、连接参数、启用状态、同步水位、最近结果和错误状态。

#### Scenario: 添加同步目标
- **WHEN** 用户填写有效配置并通过连接测试
- **THEN** 系统加密保存该配置并将其加入当前 Vault 的同步副本集合

#### Scenario: 单个目标失败
- **WHEN** 一个同步目标失败而其他目标成功
- **THEN** 系统分别记录结果，不将成功目标错误标记为失败

### Requirement: 五秒静默同步
系统 SHALL 在密码项、文件夹、设置或同步配置发生新增、修改、删除、移动后启动五秒静默计时；计时期间再次修改 MUST 重置计时。静默期结束后系统 MUST 先确保本地加密状态已保存，再开始远端同步。

#### Scenario: 连续编辑
- **WHEN** 用户在每次不足五秒的间隔内连续修改
- **THEN** 系统持续延后同步，直到最后一次修改后完整五秒无新修改

#### Scenario: 同步期间再次修改
- **WHEN** 上传某一版本期间产生新修改
- **THEN** 当前上传可完成，但新修改进入新的 dirty 代次并重新执行静默同步

### Requirement: 不可变同步身份和增量
系统 MUST 使用不可变 EntryId、FolderId、DeviceId、EventId 和单调递增设备序号标识同步对象及事件。可修改且区分大小写的 key MUST 仅作为密码项字段，不得作为 S3 对象路径或同步主键。每个增量 MUST 使用 SyncKey 认证加密，且 S3 路径不得泄露用户名、key、标题、标签或凭据。

#### Scenario: 修改密码项 key
- **WHEN** 用户将现有密码项 key 修改为新值
- **THEN** 系统为同一 EntryId 记录 key 字段变更，而不是创建新的密码项身份

#### Scenario: 重复下载事件
- **WHEN** 同一 EventId 从一个或多个 S3 副本重复下载
- **THEN** 系统只应用一次并安全忽略重复内容

### Requirement: 多副本最终收敛
系统 SHALL 从全部已确认且启用的 S3 目标拉取未知增量，在本地完成认证、去重和合并，并将本地合并后各目标缺失的事件传播到所有其他目标。

#### Scenario: 从单一副本发现修改
- **WHEN** 客户端仅从 S3-A 下载到有效新事件
- **THEN** 系统合并事件并将缺失事件传播到 S3-B、S3-C 及其他启用目标

#### Scenario: 传播环路
- **WHEN** 已传播事件之后从另一副本再次返回
- **THEN** 系统依据 EventId 和同步水位阻止重复应用及无限传播

### Requirement: 因果和冲突合并
系统 MUST 使用设备序号和因果版本判断先后关系，操作时间仅用于展示和逻辑时钟决胜，不得单独依赖设备墙上时钟。不同字段的并发更新 SHALL 自动合并；同一字段并发更新 SHALL 确定性选择结果并保留可查看的冲突记录。

#### Scenario: 不同字段并发修改
- **WHEN** 两个设备基于同一版本分别修改标题和背景颜色
- **THEN** 合并结果同时包含新标题和新颜色

#### Scenario: 同一字段并发修改
- **WHEN** 两个设备并发修改同一密码项标题
- **THEN** 系统按逻辑时钟和 DeviceId 确定当前值并保留另一版本用于冲突查看

### Requirement: 删除、唯一性和层级冲突
系统 SHALL 使用墓碑同步删除，并在删除与修改并发时优先删除但保留可恢复冲突版本。不同对象并发占用同一 key、目录移动形成环或超过三级限制时，系统 MUST 标记人工冲突，不得自动改写 key 或生成密码。

#### Scenario: 离线设备返回
- **WHEN** 长期离线设备上传包含已删除对象的旧状态
- **THEN** 系统依据墓碑阻止对象复活

#### Scenario: 并发 key 冲突
- **WHEN** 两个不同 EntryId 合并后具有完全相同且区分大小写的 key
- **THEN** 系统将二者置为冲突状态并要求用户选择保留或修改，且不得静默改名

#### Scenario: 文件夹级联删除
- **WHEN** 一个客户端删除含后代对象的文件夹
- **THEN** 系统以同一事务标识传播文件夹及后代墓碑

### Requirement: 快照压缩和设备水位
系统 SHALL 定期将已合并状态、墓碑和每个已知设备水位压缩为认证加密快照。旧增量仅在快照完整覆盖且不会导致离线设备恢复已删除数据时才能回收；必要墓碑 MUST 永久保留在压缩快照中。

#### Scenario: 新设备同步
- **WHEN** 新设备连接已有大量历史事件的副本
- **THEN** 系统先获取最新有效快照，再获取快照水位之后的增量

### Requirement: 同步配置传播确认
系统 SHALL 将 S3 配置作为加密 Vault 数据参与备份和同步，但从远端首次获得的新目标 MUST 保持待确认状态，并由用户确认后才能连接。

#### Scenario: 远端新增目标
- **WHEN** 客户端从已信任目标同步到另一个客户端添加的 S3 配置
- **THEN** 系统显示待确认提示且不会自动向新端点发送请求

### Requirement: 同步状态和反馈
系统 SHALL 为每个 S3 目标显示空闲、待同步、同步中、成功或失败状态。成功或失败 MUST 在顶部显示提示；任意目标失败或存在冲突时，密码库设置按钮及 S3 入口 MUST 显示红点。

#### Scenario: 失败后重试成功
- **WHEN** 目标曾同步失败并在后续重试成功且无剩余冲突
- **THEN** 系统更新状态、显示成功提示并移除该目标导致的红点

### Requirement: 平台关闭行为
系统 SHALL 在 Windows 关闭且存在未同步数据时提示用户，并允许等待同步完成后自动关闭。Android 和 Web MUST 尽力同步、持久化 dirty 状态并在平台允许时显示离开提示，但不得声称能够阻止系统终止进程或等待异步网络完成。

#### Scenario: Windows 等待关闭
- **WHEN** Windows 用户确认等待尚未完成的同步
- **THEN** 系统阻止应用窗口退出直到同步完成或用户明确取消等待

#### Scenario: Web 意外关闭
- **WHEN** 浏览器未允许异步同步完成便关闭页面
- **THEN** 已持久化 dirty 状态在下次启动时触发继续同步
